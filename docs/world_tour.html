BeamNG.Earth: 128-place world tour

64 regional checks + 64 additional stress cases. Every implemented geographic style has one core location. Five places are in the USA; one is in New Zealand. The remaining 122 span the rest of the world.

These are candidate neighbourhood anchors, not surveyed vehicle spawn points or game-verified camera compositions. Scout a small batch before the full run. Four cardinal street views plus one elevated district view reduce dependence on a single heading. Move obstructed anchors in world_tour.json and freeze the revised catalog before capturing both builds.

Core routing was checked against the bundled geographic polygons. The Lagos market and Funafuti stress anchors deliberately retain unresolved routing: test neutral fallback and missing small-island/coastal coverage. Routing success does not prove that building footprints or imagery exist. A missing-data result is useful evidence, not automatically a generator failure.

What to compare

Footprint and height fidelity; regional roofs/materials/window proportions; entrances and garage access; roads and sidewalk clearance; courtyards and water exclusions; paving/planting; and loading/LOD consistency. A stretch tag marks geometry the current implementation may not support, such as stilt houses, sunken homes or distinctive roof structures. Judge its fallback and record the missing capability separately from regressions.

Capture workflow

From the workspace root in PowerShell, use the launcher below. Start the desired build and Earth level first, enable Options > Advanced > MCP, park the vehicle, keep the game focused and leave it alone while capturing. Stop the server and restart BeamNG when switching builds.

.\"World tour.bat" list
.\"World tour.bat" check
.\"World tour.bat" plan --limit 3
.\"World tour.bat" run --label original --build ORIGINAL_BUILD_ID --limit 3
# After inspecting the pilot and selecting the original build again:
.\"World tour.bat" run --label original-full --build ORIGINAL_BUILD_ID
# Switch both server and mod to the modified build, then:
.\"World tour.bat" run --label modified-full --build MODIFIED_BUILD_ID
.\"World tour.bat" compare "PATH_TO_ORIGINAL_RUN" "PATH_TO_MODIFIED_RUN" --out "PATH_TO_REPORT"

Use an exact version/checkpoint identifier for --build. It records your declaration; the runner does not install, switch or authenticate a build. Keep resolution, graphics settings, render distances, vehicle, traffic and cache conditions consistent. The capture harness fixes the date, local solar time and clear weather.

# Filters combine; repeated --tag means all those tags must match.
.\"World tour.bat" run --label industrial --build BUILD_ID --tag industrial
.\"World tour.bat" run --label regional --build BUILD_ID --group core
.\"World tour.bat" run --label next-batch --build BUILD_ID --offset 16 --limit 16
.\"World tour.bat" run --label retry --build BUILD_ID --skip-completed "PREVIOUS_RUN"
.\"World tour.bat" merge "MERGED_RUN" "PREVIOUS_RUN" "RETRY_RUN"
.\"World tour.bat" restore "INTERRUPTED_RUN"

Each full run requests 640 screenshots (five per location). JPG is the default; --png is available. Allow several hours: the default settle and measurement windows alone total about 3.6 hours, before downloads and loading. Start with a small pilot or use batches. Terrain/road/import readiness is polled, followed by a 15-second settle per view. This does not prove every progressive building has reached final detail: inspect results and use --wait-backlog with a companion server started with --status-interval 1 when available. Timeouts remain visible in the run record and are not accepted by resume/merge as completed captures.

Runs go to BeamNG.EarthBuildTest/docs/research/world-tour/, with a unique folder, screenshots, catalog snapshot, build label, run.json and restore state. Ctrl+C triggers the existing harness's restore logic. If the process is killed, use restore. Resuming writes a new run and never overwrites previous images. Merge only combines the same build, catalog and capture settings.

A/B reports contain paired images, difference heatmaps and performance figures. Visual change is not automatically improvement. AGL camera placement can change when geometry beneath the camera changes; the report flags differing actual camera positions and timed-out views. The original build must expose the Earth core APIs used by tools/benchmark.lua; run check first. No captures have been claimed merely from offline validation.
